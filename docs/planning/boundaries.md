# Vocabulary boundaries, ranked

Working list (2026-11-01). Generated by `node packages/mapper/src/cli.ts boundaries color-v1` (raw list: `.cache/boundaries.json`, 71 pairs). A boundary is a pair of facet values that answers for the same token disagree on. Each needs one owner decision, recorded as a rule with a deciding test, instead of one review card per token.

Counts per pair:
- **open:** queued tokens whose answers split on it, settled by the decision.
- **decided:** tokens already decided where an agent answer was on the losing side (the precedent).
- **audit:** approved vs auditor-suggested concepts.
- **jev:** Jev confusions in its best lab run.

Score = 3 × open + 2 × audit + decided + jev / 2 + systems.

## Smaller pairs (no decision needed yet)

- Hue neighbors in one system's palette naming: brown vs yellow, blue vs indigo, cyan vs teal (3 open each). The hue rule (ADR 0017) already says the nearest canonical hue; a value check settles them.
- intent highlight vs none, intent accent vs none, usage categorical vs none: mostly Jev confusions with no open tokens.
- usage page vs surface, property background vs none, property text vs none: 1 open or fewer.

## What one decision settles

B1 to B8 cover 129 open tokens (75% of the token queue of 171), the 33 audit contradictions on these pairs, and the precedent for every future system. Where a test is computable, it becomes a deterministic step (like rank-emphasis) and a validator check, and its wording goes into the agent prompts and Jev's option descriptions.
